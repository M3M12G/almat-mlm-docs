## 7. Что ДОСТУПНО снаружи (что конкурент заберёт)

**Без аккаунта (публично):**
- Весь маркетинг, каталог, юр-документы.
- **Полный клиентский код** `app.js` (~31KB) + `style.css` (~186KB) → вся логика калькулятора бонусов, фильтров, кошелька, копирования — читается дословно.
- **Бизнес-правила кошелька и MLM** — подробно описаны в публичных юр-документах (TRON-контракт, курс НБК, дедуп, циклы).
- Медиа/PDF по `/media/{hash}`.

**С аккаунтом (регистрация ОТКРЫТА — конкурент просто регистрируется):**
- Полный кабинет: механика кошелька, персональный TRON-адрес, типы начислений (Referral/Matching/Уровневый 2%/Карьерная), 10-дневные циклы, структура до 10 линий, реф-код `FV`+id.
- Т.е. **вся партнёрская механика воспроизводима** конкурентом за 5 минут через собственную регистрацию — ровно то, что уже задокументировано в `reverse-engineering.md §1.6`.

**Вывод:** для функционального копирования конкуренту **достаточно публички + одного тестового аккаунта**. Ничего взламывать не нужно.

## 7a. Certificate Transparency (crt.sh) + поддомены — ЧИСТО

- **CT-логи:** только **1 сертификат** (Let's Encrypt, 2026-08-25), покрывает `ful-vera.com` + `www`. **Никаких** утёкших `dev`/`staging`/`api`/`admin`-поддоменов в CT. **Confidence: high.**
- **Пассивный перебор ~35 типовых поддоменов (только DNS A):** резолвятся лишь `www` (веб-IP) и `mail` (`89.35.125.9`). Скрытых сервисов не найдено.
- **Версии ассетов (build-стемпы в URL):** `style.css?v=2026082613` (≈26.08.2026), `app.js?v=2026082512` (≈25.08.2026) → мелкие правки фронта шли 25–26 августа, дальше стабильно.

**Вывод:** внешняя поверхность = **один веб-хост + почтовый хост**, staging/dev наружу не торчит. Для атакующего/конкурента дополнительных «дверей» через поддомены нет. Это хорошо.

## 9. Резюме рисков (для владельца стенда)

| Наблюдение | Риск | Приоритет |
|---|---|---|
| Origin-IP без CDN/WAF | Прямой DoS/скан origin, нет edge-защиты | средний |
| Нет DMARC + мягкий SPF | Спуфинг писем от `@ful-vera.com` (фишинг партнёров) | **высокий** |
| Нет CSP | Слабее защита от XSS | средний |
| Нет DNSSEC | Теоретический риск подмены DNS | низкий |
| Регистрация открыта | Конкурент полностью реверсит кабинет через свой аккаунт | by design (осознать) |
| Весь JS/бизнес-логика в открытом клиенте | Логику скрыть нельзя — критичные расчёты держать на сервере | by design |
| Отпечатки версий зачищены, sec-заголовки в основном есть, cookie-флаги корректны | Базовая гигиена — ОК | — |

**Главное для защиты:** (1) добавить **DMARC** (`p=reject/quarantine`) + ужесточить SPF, (2) поставить **CDN/WAF** перед origin, (3) добавить **CSP**, (4) все финансовые расчёты — только серверные (клиентский калькулятор не должен быть источником истины — сейчас он и не является, это плюс).

*Все данные получены пассивно из публичных источников (RDAP/DNS/TLS/HTTP-заголовки). Активный эксплойтинг не проводился.*
