# Gap Analysis — Wellness/MLM платформа (аналог)

> Сравнение: что **достоверно известно** о поведении ful-vera.com (наблюдалось снаружи) · что мы **предполагаем** (проектный выбор) · чего **не хватает** для полноценного аналога.
> Правило: колонка **Unknown** содержит только реальные пробелы. Догадки идут в **Assumption**, не в Unknown.
> Дата: 2026-09-21. Источник фактов: `docs/reverse-engineering.md` (внешний анализ HTML/JS/CSS/HTTP).
> **Обновление 2026-09-21:** добавлены данные из авторизованного доступа к кабинету (санкционированная сессия владельца тестового аккаунта, §1.6 reverse-engineering.md). Часть Unknown закрыта — помечено ✅ РАЗРЕШЕНО.

## Легенда
- **Known** — подтверждено наблюдением (HTML, `app.js`, `style.css`, HTTP-коды, юр-документы сайта).
- **Assumption** — наше проектное решение / обоснованная гипотеза (может не совпадать с оригиналом).
- **Unknown** — объективно не определено снаружи; **не заполняется предположениями**.
- **How to verify** — конкретный способ закрыть пробел.
- **Priority** — важность для реализации MVP-аналога: `P0` (блокер) · `P1` (важно) · `P2` (можно позже).

> Многие «verify» относятся к **нашему** аналогу (решить/спроектировать), а не к вскрытию оригинала — probing чужого прод-сайта ограничен и частично рискован (стоп safety-классификатора уже был).

## Сводка приоритетов (P0 — блокеры MVP)

### ✅ Закрыто авторизованным доступом (§1.6)
- **4 типа начисления** подтверждены: Referral / Matching / **Уровневый 2%** / Карьерная премия (Pool — предположительно Gold+). «+2% на 10 уровней» = отдельный тип.
- **Цикл** — фиксированные календарные границы (10 дней), глобальный.
- **База/условие:** начисления и прогресс только при **активированном аккаунте + оплаченном действующем пакете**; активная 1-я линия = приглашённые с активным пакетом.
- **Кошелёк:** два раздельных баланса (пополнения/комиссии), расход сперва из пополнений; статусы «ожидает»→комиссии→резерв→выплачено.
- **Структура:** до 10 линий; реф-код = `FV`+id; поле спонсора.
- **2FA** присутствует; **fallback секции** на profile; **BankDetails** маскируются.

### Остаются P0 (закрыть до разработки)
1. **MLM тонкости** (P0): точная бонусная база по реальному оплаченному заказу; глубина matching; условие квалификации каждого из 10 уровней (для «Уровневого 2%»); логика командного BV и компрессии; каскад сторно. *→ нужен формализованный маркетинг-план.*
2. **Финансовые edge-cases** (P0): возврат после выплаты (взыскание/долг), гонки резерв↔баланс, chain reorg до финализации.
3. **Кошелёк/ключи** (P0): хранение приватных ключей TRON (KMS/HSM), глубина подтверждений, интервал поллинга, выбор блокчейн-провайдера.
4. **Permissions** (P0): maker-checker для выплат; маскирование данных нижних партнёров в дереве.

**P1** — flow шага 2 регистрации, механика 2FA, background-параметры, интеграции (email, НБ РК), rate-limits, файлы, админ-финансы, серверная валидация, модель проводок кошелька.
**P2** — версионирование API, модель хранения дерева, отчёты, UI-детали ошибок, маркетинг-каналы.

## Важное замечание по методу верификации

Большинство оставшихся пробелов закрываются **проектированием собственного продукта**, а не реверс-инжинирингом прод-сайта:
- **Кабинет партнёра — раскрыт** авторизованной сессией владельца тестового аккаунта (санкционировано пользователем): секции, поля, балансы, циклы, типы начислений, структура (§1.6). **Админка** и **точные server-API** остаются недоступны (только партнёрский аккаунт, не админский).
- Активное probing чужого прод-сайта (перебор endpoint'ов, невалидные POST, нагрузочные тесты rate-limit) — **вне допустимого** (был стоп safety-классификатора на скане путей и на повторе session-cookie). Авторизованный просмотр **своего** кабинета — допустимо и выполнено.
- Легально доступны для изучения: публичные HTML/JS/CSS (изучены), внешние docs провайдеров (TronGrid, Tether, TRON, RSS НБ РК — ссылки в юр-документах).

Поэтому колонка **How to verify** для P0-бизнес-правил указывает «продуктовое решение» — эти правила должен зафиксировать **владелец продукта** (маркетинг-план, регламент выплат, KYC), а не догадка по внешнему виду.
