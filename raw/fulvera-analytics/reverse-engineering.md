# FULVERA (ful-vera.com) — Reverse Engineering / Product Analysis

> Внешний анализ по публично доступным страницам, HTML, `assets/js/app.js`, `assets/css/style.css` и поведению маршрутов (HTTP-коды, редиректы).
> Цель — понять, что нужно для функционального аналога. Реализация **не** делалась.
> Дата анализа: 2026-09-21. Оператор сайта по документам: **ТОО «Fulvera»**, Республика Казахстан.

Каждый вывод помечен: **Evidence** (на основании чего) и **Confidence** (high / medium / low).

---

## 0. TL;DR — что это

FULVERA — казахстанская wellness/БАД **e-commerce витрина + MLM-платформа** (сетевой маркетинг) с личным кабинетом партнёра и **внутренним крипто-кошельком** (учёт пополнений USD₮ TRC-20 в сети TRON, конвертация в тенге по курсу Нацбанка РК).

Сайт **сейчас в тестовом/информационном режиме**: продажи и оплата отключены, каталог состоит из «Тестовых товаров», реквизиты продавца (БИН, банк) не опубликованы.

- **Стек (внешне):** PHP (сессия `PHPSESSID`, поле `_csrf`), nginx, серверный рендеринг HTML (не SPA). **Confidence: high** — заголовок `Set-Cookie: PHPSESSID`, `Server: nginx`, полностью серверный HTML без JS-фреймворка.
- **Языки:** RU (`/`) и KK (`/kk`), переключатель языков. **Confidence: high** — `hreflang`, префикс `/kk` работает на всех страницах.
- **Ключевые домены функциональности:** каталог, корзина/заказ, регистрация/аутентификация, партнёрский кабинет, MLM-маркетинг-план (4 вида бонусов, 11 рангов), кошелёк TRON/USDT, админ-панель, обучающие материалы, геймификация, новости.

## 1.6 Детальный разбор кабинета (подтверждено сессией, 2026-09-21)

> Источник: авторизованный дамп тестового аккаунта (санкционирован пользователем). PII в этом документе не приводится — только структура полей и поведение. Все **Confidence: high**, если не указано иное.

### Общий каркас кабинета
- Двухколоночный layout: сайдбар `cabinet-nav` (список секций) + контент.
- Шапка: «Здравствуйте, {имя}», кнопка «Выйти», карточка пользователя (аватар-инициал, ФИО, `@{login}`).
- Секция активна по `is-active` + `aria-current="page"`.

### profile — Личные данные
- **Поля:** ФИО, Логин, Телефон, Email, **Номер карты** (маскирован `•••• 9990`), **Счёт** (маскирован `•••• 3706`), Дата регистрации, статус аккаунта («Активен»).
  → Подтверждает: банковские реквизиты (карта + счёт) хранятся и **показываются маскированно**.
- **Блок «Прогресс кабинета»** — вычисляемый индикатор готовности (наблюдалось «60% готовность»). Компоненты: **Полнота профиля** (N из 6 обяз. полей), **Правовые документы** (N из 3 принятых редакций), **Стартовый пакет** (выбран/не выбран), **Первый уровень** (кол-во лично приглашённых). Явно: «это не ранг и не финансовая оценка».
  → Новое: **три обязательных правовых документа** к принятию (не 8; из 8 в правовом центре — 3 требуют согласия при регистрации/активации). **Confidence: medium** (какие именно 3 — не детализировано).
- Мини-виджет ранга: текущий ранг + следующая цель + прогресс-бар (`rank-progress--light`).

### qualification — Квалификация и ранг
- **Текущий ранг:** «Партнёр» (базовый, ниже «Консультант»). «Постоянный действующий ранг» — **достигнутый ранг сохраняется** (нет даунгрейда достигнутого).
- **Условие старта прогресса:** «Новый прогресс начнётся после **активации аккаунта и оплаченного действующего пакета**» → без оплаченного активного пакета начисления/прогресс не идут. **Ключевое бизнес-правило.**
- **Следующая квалификация:** Консультант · карьерный бонус 20 000 ₸ (совпадает с публичной таблицей рангов).
- **Расчётный цикл (наблюдался конкретный):** `14.09.2026 — 24.09.2026`, «данные на 21.09.2026» → **10-дневный цикл с фиксированными календарными границами** (глобальный, не per-partner). **Confidence: high.**
- **Метрики цикла:** Личный объём (BV, «информационный показатель»), Командный объём (BV, «ваш подтверждённый BV + объём структуры»), Активная первая линия (лично приглашённые **с активным пакетом**).
- **«Ожидает зачисления»:** сумма + «в ожидании перевода на **комиссионный баланс**: N начислений» → начисления сперва «ожидают», затем переводятся в комиссионный баланс кошелька.
- **Блок «Ожидающие бонусы»** за цикл — **4 типа начислений** (важно, закрывает пробел):
  1. **RB — Реферальный бонус**
  2. **MB — Matching Bonus**
  3. **2% — Уровневый бонус 2%** ← это и есть «+2% на 10 квалифицированных уровней вверх» из публичного маркетинг-плана; в кабинете это **отдельный самостоятельный тип начисления**, не часть RB.
  4. **★ — Карьерная премия**
  → Global Pool в кабинете этого (базового) ранга **не показан** — вероятно, виден только с Gold+. **Confidence: medium.**

### wallet — Кошелёк
- **Баланс-split — ДВА раздельных баланса:**
  - **Пополнения** (deposits, из USDT) — `0,00 ₸`
  - **Комиссии** (партнёрские начисления) — `0,00 ₸`
  - «Всего доступно» = сумма; правило расходования: **«при выборе обоих источников сначала расходуются пополнения»**. **Ключевое правило учёта.**
- **Отметка проверки баланса:** «проверено 21.09.2026 · 12:05» → баланс имеет timestamp последней сверки с сетью.
- **Курс:** «USD / KZT · курс НБК = 446,56 ₸», «Актуальный кэш · 21.09.2026», «Официальный источник» → курс кэшируется на дату, тянется из НБ РК.
- **Статы:** Получено в сети (USDT), В резерве заявок (₸), Всего выплачено (₸).
- **Методы пополнения** (radio `wallet_deposit_method`):
  - `usdt_trc20` — USDT / TRON (TRC-20) — **checked, «Доступно»**.
  - Банковская карта / «Пополнение в тенге» — **«Скоро»** (disabled). → фиат-пополнение заложено, отключено.
- **Персональный TRON-адрес** (TRC-20) — уникальный на аккаунт, с кнопкой копирования (`data-copy-source="#wallet-deposit-address"`).
- **Параметры сети:** TRON (TRC-20), Минимум 1 USDT, контракт Tether `TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t`.
- **Инструкция пополнения** (3 шага): скопировать адрес → выбрать сеть TRON → после подтверждения зачисляется.
- **Курс тянется из точного RSS:** `https://nationalbank.kz/rss/rates_all.xml` (ссылка «Официальный источник» в разделе). **Confidence: high.**

**Две POST-формы кошелька** (обе `action=/kabinet?section=wallet…`, диспатч по скрытому полю `_action`, `_csrf` на форму):

1. **Сохранение платёжного профиля** (`_action=save_payment_profile`):
   | Поле | Атрибуты |
   |---|---|
   | `beneficiary_name` | required, max 160, autocomplete=name |
   | `card_number` | inputmode=numeric, cc-number, max 32, **опционально** |
   | `account_number` | max 100, **required** |
   | `bank_name` | max 160, опц. |
   | `bic` | max 32, опц. |
   | `iin` | max 12, numeric — **ИИН (индивидуальный идентификационный номер РК)** |
   | `current_password` | **required — повторная аутентификация для сохранения реквизитов** |
   → Реквизиты выплаты богаче, чем казалось: не только карта/счёт, но банк, БИК, **ИИН** (нужен для налогов/выплат в РК). Изменение защищено паролем.

2. **Заявка на вывод** (`_action=request_wallet_withdrawal`, `data-wallet-withdrawal-form`):
   | Поле | Значение/атрибут |
   |---|---|
   | `method` | `saved_details` (вывод на сохранённые реквизиты) |
   | **`idempotency_key`** | `wd:<hash>` — **генерируется сервером** (защита от дубля выплаты) |
   | `source_account` | select: **`commissions` / `deposits` / `both`** — выбор источника списания |
   | `current_password` | required — повторная аутентификация |
   | `wallet_terms` | checkbox required — согласие с условиями кошелька |
   → **В текущем состоянии вся форма `disabled`** (кнопка тоже) — вывод заблокирован (нет баланса/не пройден KYC/функция ещё не включена).

- **KYC:** ссылка **`/kabinet/kyc`** рядом с заявками (`wallet-request-list`) → **отдельный KYC-флоу как предусловие выплаты**. **Confidence: high** (роут виден), механика — unknown.
- **Пополнение картой** (`wallet_deposit_method=bank_card`) — radio `disabled` («Скоро»).

**Ключевые выводы (закрывают пробелы gap-analysis):**
- **Идемпотентность выплат — ПОДТВЕРЖДЕНА** (`idempotency_key`, сервер-генерация) — было архитектурным предположением.
- **Выбор источника вывода** (commissions/deposits/both) — прямое подтверждение двух-балансовой модели.
- **Re-auth паролем** на финансовых действиях (сохранение реквизитов + вывод).
- **KYC** обязателен для выплат.
- **ИИН** собирается для выплат (налоговая идентификация РК).

### structure — Структура
- **Сводка:** «Всего в структуре» (подпись **«Партнёров до 10-й линии»** → глубина структуры ограничена **10 линиями**), «Первая линия» (лично приглашённые), «Глубина структуры» (ур., «максимальный видимый уровень»), «BV стартовых пакетов».
- **Реферальный блок:** «Код: `FV00000029`» + ссылка `https://ful-vera.com/registraciya?ref=FV00000029` + копирование.
  → **Реф-код = `FV` + zero-padded id партнёра** (аккаунт — 29-й → `FV00000029`). Формат `FV\d{8}` подтверждён на реальных данных. **Confidence: high.**
- **Спонсор (upline):** поле «Ваш спонсор: {имя|не назначен}» — прямой upline партнёра.
- Дерево: empty-state «Структура пока пуста» → после регистрации по ссылке новый партнёр появляется на 1-й линии.

### orders — Мои заказы
- Empty-state «Заказов пока нет»; заявлено, что появятся «оплата, доставка, квитанция и доступные действия по возврату». Кнопка «Открыть корзину». → Заказы за авторизацией, привязаны к партнёру.

### materials — Материалы для продвижения
- Заголовок + «Редакция 25.08.2026».
- Файлы: «готовятся к публикации» / «появятся после двуязычной проверки владельцем» → **модерация контента владельцем перед публикацией**, привязка к языку.
- Чек-лист «Быстрый старт 0 из 5», прогресс, `data-material-storage="fulvera-materials-v1-29"` (суффикс `-29` = id партнёра) → **прогресс хранится в localStorage per-partner, НЕ на сервере**. Явно: «отметки сохраняются только в этом браузере», «это не квалификация и не условие начисления».

### Прочие секции (досмотрено 2026-09-21)
- **packages** — не покупка в кабинете, а CTA-ссылка на публичную `/partnerstvo#packages`. Выбор/оплата пакета идёт через публичную страницу (в текущем состоянии). **Confidence: high.**
- **events** — «Новости и мероприятия», ссылка на `/novosti` (агрегация публичных новостей в кабинете). **Confidence: high.**
- **contacts** — две карточки `cabinet-card` с контактами + ссылка на `/kontakty`. **Confidence: high.**
- **delivery** — заглушка (нет сохранённых адресов), CTA «Перейти в каталог». Адреса доставки появятся после заказов. **Confidence: high.**
- **Гейтинг секции:** невалидная (`?section=security`) → fallback на profile; при этом **на profile/дефолт-виде рендерятся блоки геймификации** (`game-metric` ×5, `game-achievement` ×4, часть `is-complete`) → **геймификация живёт на профиле/overview**, достижения серверные с состоянием.

### Безопасность (`/nastroyki-bezopasnosti`) — досмотрено 2026-09-21
Три блока, все POST на `/nastroyki-bezopasnosti`, диспатч по полю `action`:
- **Email:** статус «Подтверждён» → **верификация email реализована** (флаг подтверждения). **Confidence: high.**
- **2FA — TOTP** (`action=begin_totp`, требует `password`): статус «Не включена»; коды совместимы с Google/Microsoft Authenticator, 1Password (стандартный TOTP). → **2FA = TOTP-приложение, не SMS/email.** Есть **резервные коды** (упомянуты для смены пароля при активной 2FA). **Confidence: high.**
- **Смена пароля** (`action=change_password`): `password` + `new_password` + `new_password_confirmation`, **min 12 символов, «буквы и цифры»**, max 255. При активной 2FA — нужен код приложения или резервный код. **Confidence: high.**
  → **Политика паролей раскрыта:** ≥12 символов, буквенно-цифровые. Закрывает пробел AUTH.

- **KycVerification** (1:1/1:N к Partner) — загруженный документ (jpg/png/pdf), статус (`not_submitted`/pending/approved/rejected); предусловие первой выплаты. Файл в приватном хранилище.
- **TwoFactorAuth** (к User) — TOTP-секрет, статус (вкл/выкл), резервные коды.
- **EmailVerification** (к User) — флаг подтверждения email.
- **Rank** — уровень 1–11, условие (кол-во личных партнёров нужного ранга + командные BV), единовременная премия.
- **Package** — Start/Pro/Premium, цена, BV, ставка Matching.

- **Material / Task** — обучающие модули; прогресс задач у пользователя в localStorage (не на сервере).

- **Платёжный провайдер фиата** (ещё не подключён).
- **Наличие rate-limiting / WAF** (частично: заголовки безопасности есть — HSTS, X-Frame-Options, X-Content-Type-Options, Permissions-Policy).

## 10. Вывод для построения аналога (scope)

Минимальный функциональный аналог требует:

**Backend:**
- Серверный веб-фреймворк с session-auth + CSRF, серверный рендеринг (или SSR).
- i18n (RU/KK).
- Модели: User/Partner (дерево), Product, Order/Cart, Wallet, WalletTransaction, PayoutRequest, BonusAccrual, Rank, Package, News, ContactRequest, Consent, Document.
- **MLM-движок:** расчёт Referral (10-дн. циклы), Matching, Career (11 рангов), Global Pool + сторнирование.
- **Крипто-модуль:** генерация TRON-адресов, поллинг USD₮ TRC-20, дедупликация по txid+index, курс НБ РК, конвертация, заявки на выплату.
- Фоновые задачи (поллинг блокчейна, курс, расчёт бонусов, email).
- Загрузка/выдача файлов (PDF/изображения).
- Админка (CRUD).

**Frontend:**
- Публичные страницы + кабинет + админка.
- Клиентские виджеты: фильтр каталога, калькулятор бонусов, маска телефона, копирование, reveal-анимации, табы материалов, прогресс/геймификация (localStorage).
- Доступность (ARIA, focus-trap, skip-link, reduced-motion).

**Интеграции:** TRON (блокчейн), Нацбанк РК RSS, email, (позже) фиат-платежи.
