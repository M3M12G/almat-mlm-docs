# Bonus Engine — Compensation Plan

Классический **линейный (Unilevel) маркетинг-план**. Основа сети — **сбыт товара**:
пакеты START / BUSINESS / PREMIUM — это наборы продукции, ежемесячная активация —
обязательная покупка товара. Вознаграждение платится за оборот товара в структуре,
а не за сам факт регистрации.

Решения бизнеса (2026-09-21, 2026-09-22) зафиксированы в разделе «Зафиксированные правила».
Что ещё не решено — `07_open_questions.md`. Как подбирать ставки —
`10_comp_plan_calibration.md` и калибровщик `calibration/comp-plan-calibrator.html`.

Compensation plan состоит из **5 независимых механизмов начисления**, срабатывающих
на разные события (покупка / изменение ранга / конец месяца). Каждый реализуется
как отдельное правило (`bonus_rules`), не как один монолитный расчёт.

## Общий принцип: Event-Sourced Bonus Engine

```
PurchaseEvent (purchase_id, buyer_id, kind, amount_kzt, bv, created_at)
   kind ∈ { package, upgrade, activation, product }
        │
        ▼
BonusRuleEngine
        ├─► DirectBonusRule      (kind = package | upgrade)       → BonusTransaction[]
        ├─► UnilevelBonusRule    (kind = package | upgrade)       → BonusTransaction[]
        └─► QualificationUpdate  (любая покупка, включая пакет)   → покупки ЛП для ранга

RankEngine (только при активации самого партнёра, R12)
        └─► условия рангов → RankAchievement (навсегда) → RankBonusTransaction

MonthCloseJob (Quartz, 1-е число, за прошлый месяц)
        ├─► MatchingBonusRule   (от Direct/Unilevel ЛП за месяц)  → BonusTransaction[]
        └─► LeadershipPoolRule  (фонд % оборота → баллы рангов)   → BonusTransaction[]
```

Все начисления пишутся в единый **append-only ledger** (`bonus_transactions`) —
никаких изменяемых "балансов" в таблице `users`.

## Зафиксированные правила (2026-09-21; R3, R6, R9–R12 — 2026-09-22)

| # | Правило | Следствие для engine |
|---|---|---|
| R1 | План — классический линейный (Unilevel). Легален в РК; продаётся товар | Все начисления — от оборота товара |
| R2 | Вводим **BV** (бонусные баллы) у пакетов и товаров | Процентные бонусы считаются от BV, не от цены. ADR-0006 |
| R3 | **Direct** — при регистрации и апгрейде ЛП. Ставка по **текущему пакету спонсора**: START 10%, BUSINESS 15%, PREMIUM 20%. Число ЛП не ограничено | Ставка = `direct.byPackage[пакет спонсора]` на момент покупки ЛП; меняется только апгрейдом спонсора |
| R4 | **Апгрейд**: доплата разницы до старшего пакета, максимум до PREMIUM. Бонус за каждый апгрейд — по факту, с оплаченной разницы. Прыжок START → PREMIUM — один апгрейд на всю разницу | `kind = upgrade`, `bv = bv(new) − bv(old)`; downgrade нет |
| R5 | **Ежемесячная активация** обязательна — покупка товара на N ₸ | «Активный партнёр» = есть активация в календарном месяце |
| R6 | **Консультант**: 2 ЛП, у каждого покупки товара на сумму ≥ цены его пакета. **Пакет идёт в зачёт** | Флаг `qualified` у ЛП; сумма покупок включает пакет и апгрейды |
| R7 | **Ранг не теряется**, обнуления нет | `rank_achievements` — только вставка; текущий ранг = max |
| R8 | **Возвратов нет.** Бракованный товар меняется на такой же | Обмен не создаёт `PurchaseEvent`, пересчёта и сторно вверх по цепочке нет |
| R9 | **Премий за ранги 1–5 (до Директора включительно) нет.** Премии — с Серебряного директора (500 000 ₸) | Ранги 1–5 — только статус и ступень к следующему; `bonus = 0` в конфиге |
| R10 | **Unilevel** — 2% × 10 уровней **над личным спонсором**, только с регистрации (пакет) и апгрейдов до PREMIUM. С активаций не платится | `unilevel.onActivation = false`, `startAtSponsor = false` |
| R11 | **Matching** — только от моих ЛП, ставка по **моему текущему пакету**: START 5%, BUSINESS 10%, PREMIUM 15% | `matching.byPackage = [5, 10, 15]`, `depth = 1` |
| R12 | **Ранг растёт только в момент активации** — активация главная ценность | Rank engine запускается событием активации партнёра, не покупками ЛП |

## Единицы: ₸ и BV

- У каждой позиции каталога две величины: **цена, ₸** и **BV**.
- Процентные бонусы (Direct, Unilevel, Matching) считаются от BV:
  `бонус, ₸ = BV × ставка% × стоимость_1_BV`.
- **Стоимость 1 BV** (`bv_value_kzt`) — один параметр плана. При 180 ₸/BV и
  START = 18 000 ₸ / 100 BV бонус совпадает с процентом от цены.
- Для товаров с низкой маржой BV ставится ниже (цена / BV > 180) — так
  ставки плана не меняются, а выплаты с такого товара меньше.
- Премии за ранги — фиксированные суммы в ₸.
- Leadership Pool — % от оборота в ₸ (или BV × стоимость, настраивается).

| Пакет | Цена | BV (черновик) | Назначение |
|---|---|---|---|
| START | 18 000 ₸ | 100 | Стартовый набор |
| BUSINESS | 54 000 ₸ | 300 | Для активного развития |
| PREMIUM | 162 000 ₸ | 900 | Лидерский набор |
| Активация | N ₸ (черновик 9 000) | черновик 50 | Обязательная покупка в месяц |

BV пакетов и активации — **черновые**, финальные значения — по итогам калибровки.

## 1. Direct Bonus (реферальный)

Спонсор получает % от BV пакета лично приглашённого. Ставка зависит от
**текущего пакета самого спонсора** (R3), число ЛП не ограничено:

| Мой пакет | Ставка |
|---|---|
| START | 10% |
| BUSINESS | 15% |
| PREMIUM | 20% (потолок апгрейда) |

- Платится при **регистрации** ЛП (покупка пакета) и при каждом его **апгрейде** —
  с BV разницы.
- Ставка берётся по пакету спонсора на момент покупки ЛП. Апгрейд спонсора
  повышает ставку для следующих начислений; прошлые не пересчитываются.
- С активаций и прочих покупок товара Direct **не платится**.

Примеры (180 ₸/BV): ЛП купил START (100 BV) — спонсору на START 1 800 ₸,
на PREMIUM 3 600 ₸. ЛП сделал апгрейд START → PREMIUM (800 BV), спонсор на
BUSINESS — 800 × 15% × 180 = 21 600 ₸.

## 2. Unilevel Bonus

2% × 10 уровней, **только активному** в этом месяце партнёру (R10).

- 10 уровней считаются **над личным спонсором**: спонсор получает Direct,
  его аплайн на 10 уровней — по 2%.
- Платится только с **регистрации** (пакет) и **апгрейдов** до PREMIUM — с BV
  пакета или разницы. С активаций не платится.
- Неактивный получатель: уровень **сгорает** (остаётся компании). Альтернатива —
  компрессия (пропуск неактивных) — флаг `compression`, открытый вопрос.

Пример: ЛП купил START — каждому из 10 уровней 100 × 2% × 180 = 360 ₸.
Апгрейд START → PREMIUM — каждому по 800 × 2% × 180 = 2 880 ₸.

## 3. Matching Bonus

% от **фактически начисленного** партнёру бонуса (бонус на бонус), не от оборота.

- Только от **моих ЛП** (1 поколение). Ставка по **моему текущему пакету** (R11):

  | Мой пакет | Ставка |
  |---|---|
  | START | 5% |
  | BUSINESS | 10% |
  | PREMIUM | 15% |

- Считается **раз в месяц** при закрытии месяца. База (черновик) — Direct +
  Unilevel, которые ЛП заработали за этот месяц.
- Пример: ЛП заработал 100 000 ₸ → мне 5 000 / 10 000 / 15 000 ₸ при своём
  START / BUSINESS / PREMIUM.
- Влияет ли на ставку пакет ЛП — открытый вопрос (флаг `minWithInvitee`).
- Matching от Matching, премий за ранги и Pool **не платится** — иначе рекурсия.

## 4. Rank Bonus (карьерные премии)

11 рангов. **Ранг не теряется** (R7). Разовая премия — только с 6-го ранга,
Серебряного директора (R9). Ранги 1–5 — статус без выплаты.

| № | Ранг | Условие | Премия |
|---|---|---|---|
| 0 | Партнёр | Оплачен пакет | — |
| 1 | Консультант | 2 ЛП, у каждого продажи товара ≥ цены его пакета (R6) | — |
| 2 | Старший консультант | 2 ЛП с рангом ≥ Консультант | — |
| 3 | Менеджер | 2 ЛП с рангом ≥ Старший консультант | — |
| 4 | Старший менеджер | 2 ЛП с рангом ≥ Менеджер | — |
| 5 | Директор | 2 ЛП с рангом ≥ Старший менеджер | — |
| 6 | Серебряный директор | 2 ЛП с рангом ≥ Директор | 500 000 ₸ |
| 7 | Бронзовый директор | 2 ЛП с рангом ≥ Серебряный директор | 1 000 000 ₸ |
| 8 | Золотой директор | 2 ЛП с рангом ≥ Бронзовый директор | 2 000 000 ₸ |
| 9 | Платиновый директор | 2 ЛП с рангом ≥ Золотой директор | 5 000 000 ₸ |
| 10 | Бриллиантовый директор | 2 ЛП с рангом ≥ Платиновый директор | 10 000 000 ₸ |
| 11 | Амбассадор | 2 ЛП с рангом ≥ Бриллиантовый директор | 25 000 000 ₸ |

- «Покупки ЛП» для Консультанта = все покупки этого ЛП накопительно, **включая
  пакет** (R6). При пороге «≥ цены пакета» ЛП квалифицирован сразу после покупки
  пакета, то есть Консультант = 2 ЛП с оплаченным пакетом (уточнить — см.
  open questions).
- Ранг пересчитывается **только в момент активации** самого партнёра (R12).
  Если ЛП выросли в ранге, партнёр поднимется при своей следующей активации.
- Если одной активацией выполнены условия нескольких рангов подряд — премия
  платится за **каждый** пройденный ранг с премией.
- ⚠️ Условие «2 ЛП ранга N−1» даёт удвоение: для ранга N нужно минимум
  2^(N−1) Консультантов в структуре. Для Серебряного директора (первая премия) —
  от 32. В симуляциях до него никто не дошёл, то есть премий за ранги не было
  вообще — см. `10_comp_plan_calibration.md`.

## 5. Leadership Pool

% от **оборота компании за месяц** (не ветки) — в фонд, который делится между
партнёрами от ранга **Золотой директор** пропорционально баллам:

| Ранг | Баллы |
|---|---|
| Золотой директор | 1 |
| Платиновый | 3 |
| Бриллиантовый | 7 |
| Амбассадор | 15 |

Расчёт: фонд ÷ сумма баллов участников = стоимость 1 балла → × баллы участника.
Пример: фонд 2 000 000 ₸, 73 балла → 1 балл = 27 397 ₸; Амбассадор — 410 959 ₸.

- Участвуют только **активные** в этом месяце (ранг не теряется, но активация
  нужна — черновик).
- Если участников нет, фонд остаётся компании (перенос — открытый вопрос).
- Реализация — Quartz cron раз в месяц (Postgres JobStore, Quartz.Dashboard,
  ADR-0004).

## Возвраты и обмен

Возвратов нет (R8). Бракованный товар меняется на такой же:

- обмен оформляется как складская операция, **без нового `PurchaseEvent`**;
- начисления по исходной покупке **не пересчитываются и не сторнируются**;
- ledger остаётся append-only без компенсирующих записей по обменам.

Ручная корректировка начисления (ошибка оператора, фрод) — отдельная
админ-операция с причиной и записью в `audit_log`, не часть comp plan.

## Хранение правил — конфиг, не код

ADR-0003: проценты, пороги, уровни — в `bonus_rules.config_json`, не в коде.
Форма конфига совпадает с JSON, который выдаёт калибровщик (раздел
«Конфиг для bonus_rules.config_json»):

```json
{
  "bvValue": 180,
  "packages": [ { "code": "START", "price": 18000, "bv": 100 }, "…" ],
  "activation": { "price": 9000, "bv": 50, "joinMonthCounts": true },
  "direct":   { "byPackage": [10, 15, 20], "requiresActive": true, "onUpgrade": true },
  "unilevel": { "levels": 10, "rate": 2, "startAtSponsor": false, "compression": false,
                "onPackage": true, "onUpgrade": true, "onActivation": false },
  "matching": { "byPackage": [5, 10, 15], "depth": 1, "onDirect": true, "onUnilevel": true,
                "requiresActive": true, "minWithInvitee": false },
  "rank":     { "legs": 2, "qualifyMult": 1.0, "packageCounts": true, "onActivationOnly": true,
                "requiresActive": true, "ranks": [ "…" ] },
  "pool":     { "pct": 2, "base": "turnover", "minRank": 8, "requiresActive": true },
  "cap":      { "enabled": false, "pct": 50 }
}
```

На проде это пять строк `bonus_rules` (по одной на правило) с
`active_from` / `active_to`. Смена плана — новая версия строки, не правка
старой: начисления прошлых периодов ссылаются на версию, по которой посчитаны.
