# Бухучёт — подход для пилота

## Принцип

**Не писать собственный полноценный бухгалтерский модуль двойной записи для
пилота.** Это дорого по времени и юридически рискованно, если сделано неточно.

## Рекомендуемый подход

- Простая таблица проводок (`accounting_entries`: debit/credit, сумма, дата,
  ссылка на источник — покупка/бонус/выплата).
- Экспорт в Excel / формат для загрузки в 1С.
- Реальный бухгалтерский учёт (баланс, отчётность в налоговую) ведёт человек
  (аутсорс-бухгалтер) или сервис (1C:Fresh, Simple.kz, Kaspi.kz Business) —
  не автоматизируется полностью на пилоте.

## Связь с Bonus Engine

Каждая запись в `bonus_transactions` должна иметь соответствующую проводку в
`accounting_entries` — это не два независимых источника правды, а один
финансовый факт, отражённый в обеих таблицах для разных целей (bonus_transactions
— для расчёта comp plan, accounting_entries — для бухгалтерской отчётности).

## После пилота (не сейчас)

- Полноценный движок двойной записи, если объёмы вырастут настолько, что ручная
  сверка станет узким местом.
- Прямая интеграция с 1С через API/обмен файлами вместо экспорта вручную.
