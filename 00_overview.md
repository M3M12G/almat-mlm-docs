# Обзор проекта

## Что это

Сайт-пилот CRM/платформы сетевого маркетинга (аналог Атоми по духу, но собственная
модель вознаграждения). Пользователь регистрируется, приглашает других, строит
"дерево" по типу лучей (Unilevel, без ограничения по ширине и глубине), продаёт
продукцию через личные и командные покупки, получает бонусы по нескольким правилам.

## Топология сети

- **Unilevel / линейная**, "солнечные лучи" — у одного спонсора неограниченное
  число личных приглашённых (в отличие от бинара с лимитом 2 ветки).
- Без циклов: пользователь не может быть предком самому себе.
- Спонсор назначается один раз при регистрации (по умолчанию не меняется —
  зафиксировать явно, см. `07_open_questions.md`).

## Функциональный скоуп пилота

### Входит в пилот (MVP)
- Регистрация с реферальным кодом / привязкой к спонсору
- Модель сети (дерево, просмотр вниз на N уровней в ЛК)
- Каталог продуктов с ценой и BV (3 пакета START / BUSINESS / PREMIUM, товар
  для ежемесячной активации, возможно доп. товары)
- Апгрейд пакета с доплатой разницы (максимум до PREMIUM)
- Обязательная ежемесячная активация (покупка товара на N ₸) = статус «активен»
- Оформление заказа + **FreedomPay** (Result URL; mock на MVP-демо)
- Bonus Engine:
  - Direct Bonus (с регистрации и апгрейдов ЛП: 10/15/20% по своему пакету)
  - Unilevel Bonus (10 уровней над спонсором по 2%, с регистраций и апгрейдов, только активным)
  - Matching Bonus (5/10/15% по своему пакету от бонусов своих ЛП)
  - Rank Bonus (11 рангов, растёт при активации, не теряется; премии с Серебряного директора)
  - Leadership Pool (2% мирового ТО, ежемесячно, для Gold Director+)
  - Правила и черновые ставки — `03_bonus_engine.md`, калибровка — `10_comp_plan_calibration.md`
- Личный кабинет: баланс, история начислений, дерево, статус ранга
- Заявка на вывод средств (ручное подтверждение админом на пилоте)
- Базовый бухучёт: журнал проводок + экспорт в Excel/1С
- Админ-панель: пользователи, ранги, начисления, заказы

### НЕ входит в пилот (после MVP)
- Автоматические массовые выплаты (только ручная/полуручная обработка)
- Мультивалютность
- Сложные ранговые квалификации сверх заявленных 11 рангов
- Мобильное приложение (только responsive web)
- Множественные платёжные провайдеры одновременно

## Ключевой архитектурный принцип

**Compensation plan — это данные, не код.** Все проценты, пороги, условия рангов
хранятся в конфигурируемых таблицах (`bonus_rules.config_json`), чтобы изменения
маркетингового плана не требовали переписывания бизнес-логики.

**Финансовые операции — append-only ledger.** Никаких "балансов" как изменяемых
полей — только неизменяемые записи транзакций, из которых баланс агрегируется.
Это даёт аудируемость и возможность пересчёта без потери истории.
